One version covers the VS Code extension and the npm packages (`content`, `mcp-server`, `cli`). The release workflow uses the section for the tag being released as the GitHub Release notes (see [Releasing](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/contributing/releasing.md)).

## [Unreleased]

- **Steer one part of a design.** Make a section bolder, quieter, denser or roomier, distill, polish or harden it, and nothing else changes. `prepare_open_design_edit` marks the part, snapshots the design and returns what the verb means within the design system; `check_open_design_artifact` with its `editId` proves the edit: `edit-out-of-scope` for anything outside the part that changed (markup, shared CSS or pixels at desktop and phone width), `edit-no-effect` when nothing moved in the verb's direction, `edit-regression` for new findings, and the part before and after attached first. Undo restores the snapshot, newest first. The preview comment panels (VS Code, browser, Claude Desktop Chat) get one-click verb buttons, a new `open-design-edit` skill maps everyday wording to a verb, and the critic sees the last edits. [Steer one part of a design](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/steer-a-design.md)
- **Shared remote browser over CDP.** Set `OPEN_DESIGN_BROWSER_URL` to a running browser's DevTools HTTP endpoint (e.g. `http://browser:9222`) and export and check connect to it via `puppeteer.connect` instead of launching a local browser — no local install needed, so containers and CI hosts can drop their baked-in browser. The shared browser is never closed, only disconnected from (opened tabs are closed first so nothing lingers). Launch-only flags such as software WebGL still belong on the browser itself. Local launches now go through one helper, which adds `--no-sandbox` when running as root (containers, CI), where the sandbox cannot apply.
- **Claude plugin 0.4.0** runs MCP server 0.4.0 (it ran 0.3.0). The directory's copy, which uses the hosted server, moves to 0.4.0 with it.
- **Fix: ChatGPT desktop no longer stops at "I need a folder to save your designs in".** ChatGPT starts the plugin's server in the folder picked for the thread but reports no MCP roots, and 0.4.0 refused that folder and asked for `set_open_design_workspace`, which ChatGPT didn't offer the model. The server now works in the folder ChatGPT started it in, unless that's the home folder or the plugin's own install folder. The folder tools are also listed first, so hosts that keep or search only part of a long tool list still offer them.

## [0.4.0] - 2026-11-08

**Claude Desktop extension:** install `open-design-0.4.0.mcpb` from this release to update it. **ChatGPT desktop:** run `npx @feimacode/open-design-agent-kit install chatgpt`. **Claude plugin:** moves from MCP server 0.3.0 to 0.4.0.

Open Design 0.4.0 takes your brand from wherever it lives (a website, a PowerPoint template, a brand guide, CSS or a screenshot) and hands it to Claude Design; audits and redesigns live websites with a before-and-after page for the owner; designs app screens as linked, checked flows with states, sample data and device frames; exports decks as editable PowerPoint; and runs in ChatGPT desktop and, through a hosted server, in Claude and ChatGPT on the web. It collects 0.4.0-beta.1 to beta.3 plus the changes below them.

### Design systems and your brand

- **Design systems from templates, brand guides, CSS and screenshots.** `extract_open_design_design_system` takes `sources` (up to 6, with or without `url`): a PowerPoint template (`.pptx`, `.potx`: theme colours, fonts, text sizes, master logo and a `chartPalette`; the stock Office theme drafts nothing), a brand guide (labelled hex, RGB and CMYK codes, Pantone noted, typefaces), CSS, a Tailwind theme or W3C tokens JSON, page source, or a PNG screenshot (colours sampled in CIELAB, photos skipped). Each drafted value carries a `confidence` (`measured`, `declared`, `stated`, `sampled`), the most trusted wins and disagreements come back as `conflicts`. With no browser, the tool now reads the page's stylesheets too. The hosted server offers the tool with sources only. VS Code's **Import Design System** maps role-named CSS properties into `tokens.css`. [Design systems](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/design-systems.md#take-one-from-a-template-brand-guide-css-or-screenshot)
- **Brand kit from a website.** `extract_open_design_design_system` now returns `brandKit`: the logo in light and dark and on dark surfaces, the largest icon, touch and manifest icons, the social image and `theme-color`; each font's source (Google with a stylesheet, Adobe, self-hosted with a free near-match, system); measured specs for buttons, inputs (with focus style), cards, the nav and badges, with crops; voice samples with counted heading case, sentence length, person, exclamations and emoji; and imagery (hero kind, image radius and ratios, icon set). Saving it writes them into `brand.json`, copies an own brand's marks into `assets/`, and copies self-hosted font files only with `fontLicence: "confirmed"`. DESIGN.md gains a Components section. [brand.json](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/reference/brand-json.md)
- **Your own brand.** `create_open_design_design_system` takes `kind` (`own` or `reference`), a recommender `descriptor` and the extraction's `evidenceDir`, and writes `brand.json` beside `DESIGN.md`. An own brand is headed `# <Name> Design System` (no more "Inspired by" on your own brand), is recommended first unless the brief names another look, and `prepare_open_design_brief` notes it when a brief uses another system. Designs on it get `brand-off-palette`, `brand-font` and `brand-mark-missing` from the check (warnings and a note, `data-od-allow` works), the "default indigo" warning stays quiet when that indigo is your accent, and the critic judges fit against your site's screenshot, component specs and voice. An extraction now comes with `review.html`, whose check reports `brand-fidelity` with the site's value and the design system's. New tool `export_open_design_design_system` writes Claude Design's format with your logo and icons, a fonts note and a `brand.html`, with no checkout needed (also on the hosted server). `extract_open_design_design_system` gains `compareTo` to show what changed on the site since a design system was saved, without changing it. [Your own brand](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/design-systems.md#your-own-brand)
- **Better website extraction.** `extract_open_design_design_system` now hides consent banners, cookie walls and chat launchers before measuring (never clicking them), so an "Accept all" button can no longer become the brand's accent; it scrolls each page once so lazy-loaded and scroll-reveal sections count, and saves a full-page screenshot. It measures more of the token contract: the focus ring, success, warning and error colours, two secondary text tiers, row separators, a hairline card ring, and the container gutter and section padding at desktop and phone widths. A gradient button's first stop becomes the accent, with the gradient in a note. The site's own CSS variables are matched to drafted values and fill unmeasured status colours when their names are unambiguous. Every extra page is measured fully, and values that differ between pages come back as `draft.conflicts`. **Fix:** radii now follow the token contract (buttons → `--radius-sm`, cards → `--radius-md`, large featured blocks → `--radius-lg`); design systems extracted earlier have button and card radii one step off and can be re-extracted. The shared cookie-banner hiding also covers more consent managers and chat widgets in `audit_open_design_site`.
- **More pages, and tokens by what most pages use.** With no `extraUrls`, `extract_open_design_design_system` also measures up to 3 pages from the home page's navigation (pricing, product, about, docs; never sign-in, legal or careers pages), listed as `discovered`; `discover: false` turns it off. Each colour token now takes the value most pages use instead of the first page's (a dark campaign home page no longer darkens the system), with `coverage` and `scope` in `draft.sources` and coverage on conflicts, and `draft.consistency` reports how much of the site sits on the drafted tokens and the values only one page uses.
- **The accent is chosen by colour, and says how sure it is.** `extract_open_design_design_system` now groups the site's filled buttons by colour and ranks the colours on size and fold, how many controls and links use them, how colourful they are (a near-black "Sign in" no longer wins over three brand-green buttons), a declared `--brand`/`--primary`/`--accent` and the logo's colour. `draft.sources['--accent']` gains `candidates` (up to four, with crops) and `choiceConfidence`; below 0.5 the design-system skill shows the candidates and asks which is the brand's.
- **Motion as it runs.** The website extraction now watches the first page move before freezing it: load, a real hover and keyboard focus on the main button and first card, and the scroll pass. Motion tokens come from what actually moved (a Tailwind blanket `transition` no longer sets them), with `basis` in their source, and `brandKit.motion` (saved in `brand.json`) records what changes on hover and focus, how content enters on scroll (kind, distance, duration, stagger), load animation, the motion library and whether reduced motion is honoured. DESIGN.md gains a Motion section, and the critic sees the motion facts.
- **Components rebuilt from your tokens, in the review.** A design system's `review.html` gains a Components band: the site's buttons, badge, input, card and nav beside copies built only from the nearest tokens. Checking it compares each button and badge with the site's crop pixel by pixel and, under 90%, reports `brand-fidelity` naming the token family that costs the most with both values ("Primary button 81%: spacing. The site pads 14px 28px; nearest tokens give 12px 24px"); properties no token covers are notes. Component specs now record width, label, font family and letter spacing.
- **Nearest design systems, and "like this one".** A website extraction now names the three bundled design systems closest to the draft in style (`nearest`, from a versioned vector of about 20 token features: colours, radius, type scale, spacing, weights, shadows and motion) and the draft's most unusual features (`distinctive`). For a reference site the skill offers the closest one as a brand-free starting point. `recommend_open_design_design_systems` takes `like` (a design system id or an extraction's `bundleDir`) to rank by closeness to it, leaving the named one out, with `likeness` on each result.
- **Fix: sites written in `oklch()` lost their colours.** Chrome reports colours in the syntax a site writes them (`oklch()`, `lab()`, `color(display-p3 …)`, and `oklab()` for `color-mix()`), and the kit read only hex and `rgb()`. A Tailwind v4 or shadcn/ui site drafted no background, text, surface or accent with `status: "ok"` and no note, and the check, site audit, brand checks and before-and-after could report false contrast failures on such pages. Every colour reader now converts these formats; a colour wider than sRGB is drafted as its sRGB clip with the site's value kept in `draft.sources[token].original`, and an unreadable colour is named in `notes`. Design systems extracted from such sites can be re-extracted.
- **Extraction benchmark.** `npm run bench:extraction` runs the website extraction on about 110 real sites (credited from design-extract, with a held-out set of 18) and scores the drafted accent and body font against each site's officially sourced, painted truth (CIEDE2000, hit at ΔE 10). `npm run bench:evidence` re-checks the truth against the live pages. A weekly workflow runs it and opens an issue on a regression; extraction changes paste before and after numbers. [Extraction benchmark](https://github.com/feimacode/open-design-agent-kit/blob/main/evals/extraction/README.md)
- **Works with Impeccable.** Briefs include a short "Product context" from the project's `PRODUCT.md`, and note a project `DESIGN.md` when no design system is active. `set_active_design_system` takes `writeProjectDesignMd` to save the design system as the project's `DESIGN.md` (never overwriting one), and after porting to app code the agent suggests `/impeccable polish` when Impeccable is installed. [Works with Impeccable](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/impeccable.md)

### Websites: audit, redesign, before and after

- **Audit a website.** New tool `audit_open_design_site` (and the `open-design-site-audit` skill) runs the kit's own checks on a live site at desktop and phone sizes: contrast, tap targets, sideways scrolling and 320 px reflow, larger text, the first phone screen, overflowing text, template looks, plus `missing-viewport`, `missing-alt`, `broken-asset` and `page-weight`. It writes a plain-language report with the five biggest problems, marked crops and what wasn't measured, and no score. Not offered by the hosted server. [Audit a website](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/site-audit.md)
- **Template-look findings held to a measured bar.** On a live site, the audit's pattern checks (indigo glows, rows of identical cards, every card the same, actions that don't look like what they do) count as problems only when they fired on 5% or fewer of about 40 hand-made sites in the latest calibration (`npm run calibrate:taste`, `evals/taste-calibration/`); otherwise, and until the first calibration is committed, they are listed as notes. A single pattern is titled by what was seen; "Looks like a stock template" needs two or more different patterns on one page. The report names the calibration date. The design check on your own designs is unchanged.
- **Redesign a website.** A new `open-design-redesign` skill (and a "Redesign a website" surface) audits a live site, takes its brand and its content in one visit, and designs a home page and up to 3 inner pages as one linked flow that fixes the audit's top problems. `extract_open_design_design_system` gains `content: true`, which copies each page's words, calls to action, contact details, hours, prices and images verbatim into `content.json` and honours `robots.txt`, and `localizeImages` for a site the user owns. `prepare_open_design_brief` gains `redesign: { site, owned }`: the design binds the inventory with `data-od-bind`, marks rewritten text with `data-od-copy-edit` and its original, and shows a "concept, not affiliated" ribbon unless the site is the user's. The check adds `copy-edit-original-missing` and `concept-unmarked`, the design critic checks the audit's problems are gone, and publishing a page with the ribbon warns. [Redesign a website](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/redesign-a-website.md)
- **Before and after.** New tool `compare_open_design_before_after` writes a page for a redesign with a base screen: the old and new pages at desktop and phone sizes with a slider, every problem the site audit found re-checked on the new design with the same check at the same size (fixed only when it passes, otherwise still open), the copy edits beside their originals, and up to three summary lines that must cite fixed findings. One offline file, registered as a design, so it exports to PDF and publishes; a flow's published site links to it from the map. Base screens now record where they came from, and the audit and extraction record each page's screenshots. [Show the owner before and after](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/redesign-a-website.md#show-the-owner-before-and-after)

### App screens and flows

- **App screens.** A new "App screens" surface (under the new "Build an app" goal) for product screens: shell, form, table, detail, settings and search templates, and flow packs for sign-in, onboarding, paywall, settings and AI chat. Density and platform answers become exact sizes in the brief. A new `product-ui` craft doc. Dashboard moved here from Prototype. [App screens and flows](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/app-screens.md)
- **States in the check.** App screens keep each state in a `data-od-state` frame. The check renders every frame (findings name the state), attaches a states board, and reports `state-missing`, `dead-control`, `stress-overflow` and `stress-truncation`. The preview has a states bar, and the critic judges every frame.
- **Linked flows.** `prepare_open_design_brief` and `register_open_design_artifact` take a `flow` plan (screens, links, shared navigation). Screens link with real links, share `_shared/nav.html` through `data-od-include`, and can be checked together with `check_open_design_artifact` `collectionId` (`flow-broken-link`, `flow-dead-end`, `flow-unfilled`, `flow-unlinked`, `flow-nav-drift`, and `store-rules` notes for sign-up and paywall flows). Each collection check writes a `flow.html` map, and `export_open_design_artifact` `collectionId` writes one clickable prototype file. In VS Code, the Collections view opens the flow map.
- **Design from your app.** New read-only tool `scan_open_design_app` reads the app's tokens (with file and line), themes, components with their variants, and screens, and returns a design system to save from them. Briefs on it list the app's components and ask for `data-od-component` marks; the check reports `token-hardcoded` and `token-undefined`; promote and component sets reuse the marked components. `prepare_open_design_brief` takes a `baseScreen` (an image or a URL) for redesigns, shown beside the new design in the check. Not offered by the hosted server. [Design from your app](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/design-from-your-app.md)
- **Device frames.** A screen with `data-od-device` on `<body>` (`iphone`, `android`, `tablet`, `desktop-app`) gets a generic device frame drawn by the kit in every preview, the clickable prototype and PNG/JPEG exports (`shell: false` for the bare screen). The check renders it at the device's screen size and warns `device-double-frame` when the design draws its own. Web app screens are also checked at tablet widths, and every app screen gets a large-text pass (`large-text-overflow`). The platform question gains Desktop app. [App screens and flows](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/app-screens.md#device-frames)
- **Sample data.** App screens keep their records in one data file (`_shared/data.json` for a flow, `<name>.data.json` for a screen) and bind to it with `data-od-bind`, `data-od-repeat` and `data-od-format` (locale-aware currency, dates and numbers). The kit fills them in every preview, check and export; the file keeps the template. The brief asks for realistic data, the check reports `sample-data-missing`, `sample-data-thin` and `items-promised`, and promote and component sets turn the data into typed `mocks/` with a `TODO(data)` seam. [Sample data](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/app-screens.md#sample-data)
- **Task walkthrough.** A flow plan can name up to five `tasks` (name, start screen, end screen, step budget). The collection check follows the screens' real links and reports `task-unreachable` and `task-too-long`, the flow map draws each task's path, and the design critic walks every task on the screenshots under a new `task` area. App screens get a `screen-economy` check (no action on the first screen, or one picture filling it), and the app-screens questions ask for the main task. [The main task](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/app-screens.md#the-main-task)
- **Expo and NativeWind.** `prepare_open_design_component_library` gains a `nativewind` target (and `auto` picks it for any Expo or React Native app): a `global.css` light and dark theme and a Tailwind extension from the design system's tokens (a missing dark scheme is derived and marked), components on react-native-reusables or React Native core, native rules (touch targets, safe area, platform shadows, accessibility) and a gallery screen. Promote into an Expo Router app writes flow screens as routes, links as `router.push` and the shared tab bar as a `(tabs)` layout. [Expo and React Native](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/component-library.md#expo-and-react-native)
- **Publish a whole flow.** Publishing (or the `site` export of) any screen of a flow now publishes every screen, with the shared navigation filled in and the flow map as the home page, so links between screens work at the published URL. As a Claude artifact, a flow is its one-file clickable prototype.
- **Stale app design system note.** The check notes `app-design-system-stale` when the app files a saved app design system was read from changed after the scan, and suggests a re-scan.
- **Click through flows in Claude Desktop.** In the inline preview, a link to another screen of a flow opens that screen in the same view (Back returns), and the shared navigation is filled in.

### Decks and exports

- **Editable PowerPoint.** `export_open_design_artifact` takes `editable: true` with `format: "pptx"` (CLI `--editable`) and writes `exports/<name>-editable.pptx`, rebuilt from the browser's layout: text boxes with the deck's fonts, sizes and colours, list bullets, rectangles and rounded cards, cropped pictures and speaker notes. Gradients, shadows, SVG diagrams and rotated or blurred elements go on one background picture per slide, so nothing is dropped. The result lists what stayed a picture and which web fonts PowerPoint will need. The picture export stays the default, and publishing a deck to Canva now uses the editable file. [Editable PowerPoint](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/export-decks.md#editable-powerpoint)
- Add a Pinterest Pin export preset at 1000×1500 px with a 20 MB upload budget.

### Claude, ChatGPT and the hosted server

- **The inline preview follows edits.** In Claude Desktop Chat and Cowork, a design shown in the conversation updates in place after each round, so Claude shows it once. It waits while you write a comment, checks less often when idle and not while hidden. [Inline preview](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/guides/inline-preview.md)
- **The inline preview doesn't ask Claude to show the design again** after "Ask Claude to apply" or "Fix this piece", since the shown design already updates in place.
- **The live preview in the Code tab's Browser pane, set up for you.** Ask Claude to show the live preview and it adds an `open-design-preview` entry to `.claude/launch.json` (new tool `set_up_open_design_browser_pane`) and starts it. Each project gets its own port (5317–5416), the entry uses the `npx` beside your Node, and the pane opens the newest design (`preview --root-latest`). [Claude Desktop](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/getting-started/claude-desktop.md#the-live-preview-in-the-browser-pane)
- **ChatGPT desktop.** Each release now carries `open-design-chatgpt-plugin-<version>.zip`, a ChatGPT "Desktop only" plugin with the same skills as Codex and the server bundled in. `npx @feimacode/open-design-agent-kit install chatgpt` puts it in ChatGPT's personal plugin list (`uninstall chatgpt` removes it); it runs in the Work and Codex tabs and saves designs in Documents/Open Design. [ChatGPT desktop](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/getting-started/chatgpt-desktop.md)
- **Inline preview in ChatGPT.** The preview view asks ChatGPT for fullscreen through its own API when the standard request isn't available, and the render tools carry ChatGPT's short status lines while they run. `scripts/probe-mcp-apps-host/` records what a host supports.
- **Hosted gateway for the directory listings.** A new `packages/mcp-gateway`, shipped as the `ghcr.io/feimacode/open-design-gateway` image, serves Open Design for the Claude connector directory and the ChatGPT plugin directory. Every other install keeps the local server. [Hosted server](https://github.com/feimacode/open-design-agent-kit/blob/main/docs/reference/remote-server.md)
  - Projects with handles (`start_open_design_project`) instead of one folder per connection, kept 7 days without an account.
  - Optional sign-in through feima-idp, with a project library (`list_open_design_projects`, `claim_open_design_project`).
  - Read-only viewer and share links on a separate domain.
  - Long exports run as jobs (`get_open_design_export_status`).
  - OpenAI domain verification and a read-only maintenance switch.
  - A privacy policy and terms that cover hosted data.
- **Hosted server shows the Open Design icon.** The gateway now names itself "Open Design" with icons in its MCP server info, and serves the icon at `/favicon.ico`, `/icon.svg`, `/icon.png` and `/apple-touch-icon.png` plus a small home page that links them. Connector setup screens and chat avatars in Claude and ChatGPT used to fall back to the feimacode.com icon.
