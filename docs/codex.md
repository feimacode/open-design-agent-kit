# Using Open Design with Codex CLI

Verified against Codex's own current docs (`developers.openai.com/codex`) while building this. Two updates from what was originally assumed when this integration was planned: Codex now has its own MCP support (TOML-configured, not the JSON `.mcp.json` shape Claude Code uses) *and* its own Skills system with a `SKILL.md` format shaped just like Claude Code's (`name` + `description` frontmatter). There's also a broader "universal plugin directory" shared between ChatGPT and Codex — that requires submitting through OpenAI's own distribution process, which is out of scope here; the two things below work today with nothing to submit anywhere.

## 1. Register the MCP server

Either run:

```bash
codex mcp add open-design -- npx -y @feimacode/open-design-agent-kit-mcp
```

or add this to `~/.codex/config.toml` (or a project-scoped `.codex/config.toml`) by hand:

```toml
[mcp_servers.open-design]
command = "npx"
args = ["-y", "@feimacode/open-design-agent-kit-mcp"]
```

This is the same server the Claude Code plugin uses — nothing Codex-specific needed on the server side. Once registered, run `codex mcp list` to confirm it connected, and the nine `list_open_design_skills` / `prepare_open_design_brief` / `register_open_design_artifact` / etc. tools become available like any other MCP tool.

## 2. Add the skills (optional, recommended)

Codex discovers skills from `.agents/skills/<name>/SKILL.md` at your repository root (also `$CWD/.agents/skills`, user-scope `$HOME/.agents/skills`). This repo ships a ready-made `.agents/skills/` directory at its own root — generated by `packages/codex/scripts/generate-codex-skills.mjs` as part of `npm run sync-content`, from the exact same curated-entry list and overview skill the Claude Code plugin uses (`packages/claude-plugin/skills/`). It contains:

- `.agents/skills/open-design/SKILL.md` — the overview skill, a verbatim copy of the Claude Code plugin's authored version. Auto-triggers on design requests the same way there.
- One `.agents/skills/<id>/SKILL.md` per curated entry (e.g. `.agents/skills/guizang-ppt/`), each paired with a sibling `agents/openai.yaml` setting `policy.allow_implicit_invocation: false` — Codex's documented way to make a skill explicit-only, matching the curated shortcuts' "pinned, not auto-triggered" behavior on every other host.

Copy the whole `.agents/skills/` directory into your own project, or point Codex at this repo directly if you're working from within it — nothing needs rewriting; Codex's skill shape matches Claude Code's closely enough that the same generated files work verbatim.

## What this repo does not do for you

Neither this repo's build nor its MCP server will ever edit `~/.codex/config.toml`, your project's `.agents/skills/`, or any other file outside a workspace it's explicitly asked to operate in. Registering the MCP server is a command/config edit you run yourself; `.agents/skills/` is generated into *this* repo, for you to copy — nothing reaches into your project automatically.

## If this drifts out of date

Codex's own extensibility surface was genuinely different (and thinner) when this plan was first written a short time before this doc — re-check `https://developers.openai.com/codex` before assuming anything above still holds, especially the config.toml field names and the skill discovery paths.
