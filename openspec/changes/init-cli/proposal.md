## Why

The Claude Code plugin and the Codex `.agents/skills/` directory this repo already generates are both currently reachable only by adding this repo as a plugin marketplace, or by manually copying files out of a clone of it. OpenSpec (`openspec init`) shows a simpler, more universal pattern for this exact problem: a published, `npx`-able CLI that writes an agent's own native skill/MCP conventions directly into the *caller's* project, with no marketplace or manual copying at all. This adds that path as a second, complementary way to install OpenDesign, reusing content this repo already generates rather than duplicating it.

## What Changes

- New package `packages/cli`, published as `@feimacode/open-design-agent-kit` with `bin: { "open-design-agent-kit": ... }`, so `npx @feimacode/open-design-agent-kit init` (or `npx open-design-agent-kit init` once installed) works the way `npx openspec init` does today.
- `init [path]` command (default `.`, target is the caller's own project): an interactive checkbox prompt to choose `claude` and/or `codex` (or non-interactive via `--tools claude,codex` / `--tools all`), then for each selected tool:
  - **claude**: writes `.claude/skills/open-design/SKILL.md` plus one `.claude/skills/<id>/SKILL.md` per curated entry into the target project (Claude Code's plain `.claude/` standalone skill convention — confirmed to exist alongside, not instead of, the plugin system), and merges an `open-design` entry into the target project's `.mcp.json`, preserving any other MCP servers already configured there.
  - **codex**: copies this repo's already-generated `.agents/skills/` tree into the target project's `.agents/skills/`, and writes a project-scoped `.codex/config.toml` `[mcp_servers.open-design]` registration — but only when that file doesn't already exist; when it does, prints the snippet instead of touching it (see design.md for why).
- Re-running `init` is safe: skill files are pure generated content and get fully regenerated; `.mcp.json`/`.codex/config.toml` only ever have their own `open-design` entry touched.
- This is explicitly additive to the existing Claude Code plugin (`packages/claude-plugin`) and Codex docs (`docs/codex.md`) — a faster, no-marketplace alternative for the same two hosts, not a replacement.

## Capabilities

### New Capabilities
- `open-design-init-cli`: a published npm package providing an `init` command that writes OpenDesign's Claude Code and Codex integration directly into a caller's own project, without a plugin marketplace or manual file copying.

### Modified Capabilities
- none — this reuses `packages/claude-plugin`'s and `packages/codex`'s already-generated content as a data source; neither of those capabilities' own requirements change.

## Impact

- New package: `packages/cli` (`@feimacode/open-design-agent-kit`), with `commander` and `@inquirer/prompts` as new dependencies.
- Reads (does not modify) `packages/claude-plugin/skills/` and the repo-root `.agents/skills/` as its source content — both already regenerated by `npm run sync-content`, so `init` always ships whatever this repo's most recent sync produced.
- No changes to `packages/core`, `packages/content`, `packages/mcp-server`, `packages/vscode`, `packages/claude-plugin`, or `packages/codex` themselves.
- No implementation in this round — this proposal, its design, and its task list are the planning artifacts; building starts only once explicitly approved.
