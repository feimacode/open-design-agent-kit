## 1. `packages/cli` scaffold

- [x] 1.1 Created `packages/cli` (`@feimacode/open-design-agent-kit`), `bin: { "open-design-agent-kit": "out/index.js" }`, `commander` + `@inquirer/prompts` dependencies (plus `smol-toml` for the read-only TOML existence check — see task 4.2)
- [x] 1.2 Bundled-content strategy decided: `packages/cli` vendors a mechanical, drift-guarded copy of `packages/claude-plugin/skills/` and the repo-root `.agents/skills/` into its own `assets/claude-skills/` and `assets/codex-skills/` (`scripts/copy-skill-content.mjs`), rather than depending on either at runtime — both are `private: true` workspace-only packages that will never be published, so a real npm dependency on them isn't possible once `@feimacode/open-design-agent-kit` is actually published. Drift guard `check-cli-assets-sync.mjs` added as this package's `lint` script, verified by deliberately introducing both a content edit and a missing file, confirming both are caught with the exact affected path named, then regenerating and confirming clean. Wired into root `npm run sync-content`.
- [x] 1.3 **Deviation from the plan, found while implementing**: no esbuild bundle needed. The premise ("since packages/core, if referenced at all, has no compiled output") turned out false — `packages/cli` ended up with zero dependency on `packages/core`/`packages/content` (the vendored-assets strategy in 1.2 means it never needs their TS source at runtime), and its only dependencies (`commander`, `@inquirer/prompts`, `smol-toml`) are all normal, already-published npm packages with no TS-source-resolution problem to solve. Used plain `tsc -p .` instead — simpler, and confirmed the `#!/usr/bin/env node` shebang survives tsc's CommonJS output unmodified (checked the compiled file directly, not assumed).
- [x] 1.4 `init [path]` command registered via `commander`, default path `.`, `--tools <list|all>` flag — `src/index.ts`
